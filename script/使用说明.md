# 车满满批量开单助手 使用说明

脚本版本 `v1.2.1`。在 `v1.1.0` 基础上加固鲁棒性（断点续跑、关闭确认、慢网络超时放宽）并修正窗口定位，处理判定与经过实站验收的 `v1.0.13` 一致。

---

## 一、装好它

1. 浏览器用最新版 **Chrome 或 Edge**（其他浏览器不支持本脚本读取 Excel 的方式）。
2. 装好油猴（Tampermonkey）扩展。
3. 把本文件夹里的 `油猴批量串行自动填写保存.user.js` 拖进油猴安装。
4. **在油猴里把其他车满满相关的脚本全部停用**，只留这一个。同一个页面上跑两个脚本会互相打架，脚本检测到会直接拒绝运行。
5. 正常登录车满满，打开开单页面，等页面加载完。

装好后，页面右下角会出现一个蓝色圆形按钮 —— 那就是助手。点它打开窗口，再点「收起」变回小球。窗口可以按住标题栏拖到任何位置，位置会被记住。

---

## 二、跑一批订单

### 1. 导入表格

打开窗口，把 Excel 拖进虚线框里，或者点一下选择文件。

表格要求：`.xlsx` 格式，一次 1–100 条订单。

- 表格没问题 → 显示文件名、订单条数和前几条的预览。
- 表格有问题 → 逐条列出哪一行、哪一列要改，**整批都不会开始**。按提示改完 Excel，再拖一次就行。

### 2. 开始

点「开始处理」，会弹出一个确认窗口，告诉你即将真实创建并保存多少条订单。**点了确认，脚本才会真的动手。**

### 3. 看着它跑

进度条显示做到第几条，下面一行小字说明当前这一单正在做什么。

脚本严格一条一条来：开一张新运单 → 填 12 个字段 → 逐个核对填对了没 → 保存 → 确认网站真的保存成功了 → 才开下一单。任何一步不对，它会**停下来问你**，绝不会蒙着头往下做。

跑的过程中随时可以点「暂停」或「停止」。

> 跑的时候别去手工切换、修改或关闭脚本正在处理的页签。需要你动手时，窗口里会写清楚。
>
> 另外两点：**别把这个标签页切到后台**（浏览器会拖慢后台页面，容易误判超时，脚本发现后会在状态栏提醒你）；运行中如果误点了关闭或刷新，浏览器会先弹出确认框拦一下。

### 4. 跑完

显示成功多少条、放弃多少条，报告会自动下载到你的下载文件夹。点「新建一批」就能处理下一份表格。

## 三、需要你动手的时候

出问题时，窗口顶部会弹出一张橙色卡片，里面写两句话：**发生了什么** 和 **你该怎么办**，下面是对应的按钮。照着做就行，不用懂技术细节。

同时右下角的小球会变成橙色并显示待处理的条数 —— 就算窗口收起来了也看得见。

常见的几种情况：

| 卡片说什么 | 你要做什么 |
|---|---|
| 这一单结果不确定 | 去网站的订单列表搜一下这条记录。找得到点「已经保存了」，找不到点「没有生成，重新来」。 |
| 网站要你确认一下 | 网站自己弹了确认提示。核对没问题点「继续保存」，有疑问点「放弃这一单」。 |
| 这一单没能填完 / 没保存成功 | 在网站上手工把这一单补齐，然后点「我已改好，继续保存」。 |
| 运单号没有往下走 | 网站给的新单号和上一单一样或更小。先去确认上一单是不是真的保存成功了。 |
| 没等到「创建运单」按钮 / 有好几个创建入口 | 把多余的开单页签关掉，只留一个，再点「重新检查」。 |
| 有个页签没能关掉 | 手工把那个页签关掉，再点「我已关好」。 |
| 订单已保存，本机记录没写上 | 订单在网站上是成功的。清理一下浏览器存储，再点「重试记录」。 |

**重要：脚本停在哪一单，后面的订单就全都在排队等。** 卡片下面会写还有几条在等你。处理完当前这一单，剩下的会自动接着跑（除非你之前点过「停止」）。

窗口里的「订单明细」折叠区可以展开，看每一条订单的状态，也能按「仅人工项 / 仅异常 / 仅已保存」筛选。

## 四、中途关了浏览器怎么办

脚本会在本机记住没做完的批次。重新打开页面后：

- 窗口顶部出现橙色横幅「上次还有没做完的批次」。
- **还没走到保存那一步的订单会自动重新排队**（网站重开后会自动清理没选中的旧页签，所以这些单直接重做就行）。没有标橙的订单时，点「继续」（会再让你确认一次真实保存）就接着跑。
- **已经点过保存但结果没确认的订单会标橙**，必须先去网站的订单列表核对：找得到点「已经保存了」，找不到点「没有生成，重新来」。处理完标橙的再点「继续」。
- 不想要了就点「清除未完成记录」—— 注意网站上遗留的页签脚本不会帮你关，得你自己处理。

另外，已经成功开过的订单会被记在本机。同一份表格再导入一次会被拦下来，防止重复下单。确实要重做的话，点「这些订单确实要重做」解除。

---

## 五、报告

- 每批跑完自动下载一份报告，也可以随时点「导出报告」手动导出。
- 报告里**不含**姓名、手机号、完整运单号，只有订单编号、状态、错误分类和运单号后几位。

## 六、开发者参考

以下内容普通使用者不需要关心。

### 隐藏的调试模式

在窗口标题栏上**连点版本号 5 次**（3 秒内）开启，再连点 5 次关闭。开启后会额外显示：

- 「导出诊断JSON」按钮 —— 遇到「结果不确定」时导出这个文件发给开发者。
- 每条订单的原始技术文本、内部状态名和错误码。
- 状态栏的原始文案、已挡下的意外保存次数。

调试模式开关记在 `localStorage` 的 `cm-batch-ui-debug-v1`。以后要彻底去掉诊断 JSON，删掉这个开关即可，`#diagnostic` 按钮保留在 DOM 里但永久隐藏。

### Excel Schema v1.0

工作表必须叫 `导入数据`。必需列（顺序不限，但列名要一字不差）：

`schema_version`、`batch_id`、`source_record_id`、`source_label`、`destination_text`、`delivery_type`、`sender_name`、`receiver_name`、`receiver_mobile`、`goods_name`、`package`、`quantity`、`weight`、`volume`、`freight`、`payment_type`

- `schema_version` 必须是 `v1.0`；同一份文件里 `batch_id` 必须一致；`source_record_id` 不能重复。
- `delivery_type` 只能是 `delivery` 或 `pickup`；`payment_type` 目前只支持 `pay_billing`。
- `quantity` 正整数；`freight` 非负、最多两位小数；`weight`/`volume` 可留空或非负数。
- 不允许公式单元格，不允许用字符串 `null`/`undefined` 表示空值。
- 单货物行；一次 1–100 条。

### 执行与安全约束

- 严格串行：任意时刻最多一个未完成订单、一个保存请求。
- 12 字段全部回读通过才允许保存；未通过不保存。
- 未授权的保存按钮点击、F9 以及额外的 `/coHandle` 请求会被拦截。
- 保存响应依次由当前 Fetch/XHR、页面真实执行环境的 Fetch/XHR、`Response.json/text` 和 Performance Resource 观察；只有取得可解析响应并确认 `errno=0` 才自动判定成功。
- 保存成功后至少等待 6 秒，让网站完成订单列表和 `/oinfo` 异步刷新（慢网络下这个窗口会变长）；随后等待唯一的「创建运单」入口连续稳定 500ms（最长 30 秒），再单击一次。
- 网站替换页签/表单 DOM 时，只在完整运单号一致时自动重绑并重新核对普通字段。
- 下一单运单号必须与上一已保存单不同；同长度纯数字还必须递增。
- 保存成功的页签不会自动关闭；脚本只关闭已安全确认的同号空白重复页签，或用户明确放弃的未保存页签。
- 检查点存在 `cm-batch-serial-checkpoint-v3`，防重复台账存在 `cm-batch-order-ledger-v1`；v1.0.0 的并行检查点禁止自动恢复。

### v1.2.1 的改动范围

只改界面定位，引擎侧未动。展开/收起「订单明细」以及阶段切换会改变窗口高度，此前窗口位置不会跟着调整，贴近屏幕底部时会长出可视区、必须手工拖回来。现在内容高度变化后会自动把窗口夹回屏幕内（复用原有的边界夹取逻辑）；拖动过程中不干预，自动避让也不会覆盖你手工拖到的位置。

### v1.2.0 的改动范围

不改变任何状态机转移判定、保存门禁、拦截守卫和字段回读逻辑。改动仅限：

- **断点续跑**：检查点恢复时，从未触发过保存请求的状态一律重排为「排队等待」，并强制先走开单页签预检（`creationAttempted=true`）；点过保存的仍要人工核对，防止重复下单。
- **关闭确认**：批次运行中或保存请求未结束时，关闭/刷新页面会弹浏览器确认框。
- **后台提醒**：批次运行中页面切到后台会在状态栏警告（浏览器节流会误判超时）。
- **超时放宽**（提为顶部命名常量）：保存响应等待 20s→60s，保存后冷却 3s→6s，创建入口/结果 15s→30s，页签切换 5s→10s，重绑 8s→15s，候选与确认等待约 ×2。只推迟失败判定，成功路径不受影响。
- **防御性加固**：catch 内 `error?.xxx` 可空访问；检查点写入失败时裁剪诊断事件重试一次；`unlockDuplicates` 的台账写入补 try；新增 `error`/`unhandledrejection` 只记录诊断的监听；损坏 XLSX 报中文错误；`baselineTabs` 改用 WeakSet。

### v1.1.0 的改动范围

只重做界面。引擎侧 128 个函数逐字节未变（含全部拦截、校验、填写、下拉、回读、保存、持久化和报告构建逻辑）。改动仅限：

- 界面函数 `initializeUi` / `buildPanelHtml` / `renderSummary` / `taskActions` / `actionButton` / `stateLabel` / `taskExplanation` / `setStatus` 整体重写，并新增 17 个界面辅助函数；
- 7 处 `window.confirm` 改为应用内弹窗 `uiConfirm`（每处一行，语义等价；`unlockDuplicates` 与 `discardRecoveredBatch` 因此改为 `async`）；
- `SCRIPT_VERSION` 与 `@version` 由 `1.0.13` 升至 `1.1.0`。

授权门禁本身没有改动：`state.authorization` 仍由 `startBatch` / `resumeBatch` / `maybeAutoResume` 判断，界面只是把原来的勾选框换成了点「开始」/「继续」时的确认弹窗（隐藏的 `#authorize` 复选框仍在 DOM 中，`resetForNewBatch` 的直接写入照常生效）。
