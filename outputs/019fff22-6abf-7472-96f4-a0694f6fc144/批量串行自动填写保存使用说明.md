# 车满满批量串行自动填写保存脚本 v1.0.13

> 验收状态：2026-08-14 已完成连续 6 条实站测试；6/6 保存成功、72/72 字段回读通过，运单号后缀 071～076 严格递增，正式流程全部功能测试成功。

## 安装前准备

- 在油猴中安装 `油猴批量串行自动填写保存.user.js`。
- 停用旧正式并行版、填表测试版、串行测试版和内部页签探针；同一页面只运行本正式版。
- 使用最新版 Chrome 或 Edge，并正常登录有权创建运单的车满满账号。

## Excel 范围

接受 `.xlsx` 文件中的“导入数据”工作表，Schema 必须为 `v1.0`，每份 1–100 条。必需列为：

`schema_version`、`batch_id`、`source_record_id`、`source_label`、`destination_text`、`delivery_type`、`sender_name`、`receiver_name`、`receiver_mobile`、`goods_name`、`package`、`quantity`、`weight`、`volume`、`freight`、`payment_type`。

当前支持单货物行、`delivery/pickup` 和 `pay_billing`。表头、公式、重复记录、必填字段、枚举及数字格式任一预检失败，整批不会启动。

## 正常流程

1. 打开车满满订单页面并等待加载完成。
2. 在右下角面板选择 Excel，确认整批预检通过。
3. 勾选真实保存授权，点击“开始”。
4. 如果页面已有唯一空白“创建运单”页签，脚本直接复用；若有多个同运单号空白页签，脚本确认它们仍为空后自动关闭重复项，只保留一个。
5. 脚本严格逐条执行：取得空白页签 → 读取运单号 → 填写12字段 → 全量回读 → 保存 → 明确收到成功响应 → 保留成功页签。
6. 保存响应处理结束后，脚本先等待至少3秒，让网站完成订单列表和 `/oinfo` 异步刷新；随后等待唯一的“创建运单”入口连续稳定 500ms（最长15秒），然后只单击一次并观察新页签/表单。
7. 如果网站刷新时替换了当前页签或表单DOM，脚本只在重新读取的完整运单号与当前任务完全相同时自动重绑，并重新核对/补写普通字段；无法唯一确认时停止。
8. 每个新运单通常会自动切到新页签、聚焦到站并显示菜单。脚本创建绑定后立即核对活动页签和活动表单；如果目标订单已经活动，后续 `switchToTask` 不再点击页签。随后确认活动控件就是到站且菜单可见，满足时直接使用。只有目标订单或菜单确实未活动时才执行切换/分阶段打开。
9. 全部订单保存成功或明确放弃后，自动删除完整检查点并导出脱敏 CSV 报告。

脚本读取当前页面运单号。下一单号码必须与上一已保存订单不同；两者都是同长度纯数字时，新号码还必须更大。无法唯一读取、号码相同或未递增时，会在填写前暂停。

## 人工处理

- `errno=320`：整批暂停，只能“继续保存”或“放弃本单”，没有暂时跳过。
- 填写失败或明确保存失败：保留当前页签；人工修正后点击“修正后验证保存”，或放弃并关闭。
- 结果不确定：先查询订单列表，再选择“确认已保存”或“确认未生成并重排”；脚本不会盲目重试。
- 若仍出现结果不确定，立即点击面板“导出诊断JSON”，将文件发给开发者。诊断文件记录各捕获层的时间线，但不包含请求体、Cookie、Token、姓名、手机号、完整地址、完整运单号或原始响应正文。
- 创建入口异常：15秒内没有稳定出现、同时出现多个入口，或单击后没有观察到新页签/表单时暂停；点击“重新检查并创建下一单”前应先确认页面状态。
- 运单号异常：可关闭当前未保存页签并重新创建，或明确放弃。

人工处理使当前单达到“保存成功”或“放弃并关闭”后，剩余队列自动继续；如果此前主动点击了“停止”，则不会自动继续。

## 中断恢复和旧版迁移

- v1.0.13 未完成批次会在浏览器本地保存版本化检查点，包含恢复所需的完整订单数据和脱敏诊断时间线。
- v1.0.3 的“保存成功待关闭”记录会迁移成“保存成功、页签保留”，不会再次执行关闭。
- 刷新后不会自动执行；保存中断的订单转为“结果不确定”，其他已开始订单要求人工核对。
- v1.0.0 并行检查点禁止自动恢复。先人工处理遗留页签，再点击“放弃中断批次”删除旧检查点。
- 已明确成功的记录写入防重复台账；再次导入默认阻止，只有明确确认后才可解除保护。

## 报告和安全限制

- 报告不包含姓名、手机号或完整运单号；只记录运单号后缀和哈希、字段状态、错误分类、保存结果及身份指纹。
- 未通过12字段回读的订单不会保存。
- 未授权保存按钮、F9及额外 `/coHandle` 请求会被拦截。
- 保存响应依次由当前 Fetch/XHR、页面真实执行环境的 Fetch/XHR、`Response.json/text` 和 Performance Resource 观察；只有取得可解析响应并确认 `errno=0` 才自动判定成功。
- 到站候选超时的诊断会记录 `candidate_retry/candidate_timeout`；送货方式或付款方式首次未打开菜单时记录 `choice_retry`。同时记录 `.fn-dropdown__menu` 的总数/可见数/精确候选数及联想资源时序，不记录搜索文本。
- 每次菜单处理记录 `dropdown_open_attempt`；`already_open_for_active_control` 表示复用网站自动打开的到站菜单，其他路径记录菜单在哪个事件阶段出现及过程中峰值可见数，不记录候选内容。
- 每次订单上下文确认记录 `task_switch`：包含切换前是否已经活动、是否实际点击页签、当前焦点字段和可见菜单数。
- 任意时刻最多一个未完成订单和一个保存请求。
- 保存成功的页签不会自动关闭。脚本只会关闭已经安全确认的同号空白重复页签，或用户明确放弃的未保存页签；运行前其他页签不受影响。
- 执行期间不要手动切换、修改或关闭脚本正在处理的页签；需要人工处理时按面板提示操作。
